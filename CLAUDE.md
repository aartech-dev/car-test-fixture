# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is a mechanical CAD design project, not application software. It's a "vibe coded" 3D-printable
test fixture for slot cars: a two-part **setup block** (a **lid** with track slot / braid channels /
tire clearance pockets, and a **box** enclosure with rebate + banana-socket holes for powering the
track). There is no build system, test suite, linter, or package manifest — the "code" is a handful of
Python scripts that use the `cadquery` library to parametrically generate CAD geometry, which is then
exported as STEP files.

## Running the generator scripts

The scripts require `cadquery` (OCC-based CAD kernel bindings), which is not a plain pip install on most
systems — it's typically installed via conda/mamba:

```bash
conda install -c conda-forge -c cadquery cadquery=2
python3 setup_block_metric_v6.py
```

**Important:** each script's `cq.exporters.export(...)` calls write to hardcoded absolute paths under
`/home/claude/...` (a leftover from the sandbox they were originally authored in), not to the repo
directory. The `.step` files already checked into the repo root were copied in after generation. If you
regenerate geometry, either edit the export paths to point into this repo or copy the resulting files
here afterward — don't assume running a script updates the repo's `.step` files in place.

There's no formal test suite. Each generator script ends with a "Verify" section that prints computed
dimensions (bounding boxes, slice volumes, hole positions) with inline `# expect ...` comments — this is
the project's correctness check. When modifying geometry, update these expected values alongside the
geometry change and re-run the script to confirm the printed actuals still match.

## Architecture

- **`setup_block_metric_v6.py`** — current/latest generator. Supersedes `v4` (kept in-tree for
  reference/history, not maintained). Produces two solids from one shared set of parameters, since the
  lid and box must fit together:
  - **Lid**: a flat block with a guide-pin slot, two braid channels (with cross feed-through slots), two
    tire clearance pockets, and a rebated tongue running around all four edges on the underside.
  - **Box**: an enclosure sized to the same external length/width as the lid, with a rim rebate that
    receives the lid's tongue (offset by `FIT_CLEARANCE` per side for a friction fit), an internal
    cavity, and drilled banana-socket holes through the walls (two on one short wall, three on the
    opposite short wall in v6).
  All dimensions are parameterized in mm at the top of the file (block size, slot/channel dimensions,
  rebate depth, wall thickness, socket hole diameter/spacing) — geometry is built with
  boolean cut/union operations off a small `box_at(l, w, h, x, y, z)` helper, not sketched by hand.
- **`setup_block_metric_v4.py`** — earlier version without the third bank of banana sockets. Left for
  history; prefer editing v6 for new changes, don't fix bugs in v4 unless asked.
- **`make_coupons.py`** — a separate, smaller script that prints just one L-shaped corner of the lid
  tongue and matching box-corner rebates at several `CLEARANCES` values. Its purpose is to physically
  test-print small coupons to find the right friction-fit clearance *before* committing to printing the
  full-size box/lid — its joint geometry constants (`BLOCK_T`, `REBATE_IN`, `REBATE_DEPTH`, `BOX_WALL`,
  `BOX_FLOOR`) must be kept in sync with the corresponding values in the full setup-block script.
- **`Unnamed.FCStd` / `Unnamed.20260629-110934.FCBak`** — a FreeCAD scratch/viewer file and its
  autosave backup; not generated by the Python scripts and not clearly wired into the rest of the
  project.
- **`.step` files in the repo root** — exported outputs of the generator scripts (both the full
  setup-block lid/box for v4 and v6, and the corner-fit coupons), checked in directly rather than built
  in CI.

## Conventions in the generator scripts

- All dimensions are millimeters; imperial-derived measurements (e.g. slot widths matching HO/1:64
  slot-car track and braid dimensions) are given as their mm equivalents, not fractions.
- Geometry is composed by boolean-cutting rectangular prisms and profile extrusions from the
  `box_at()`/`open_ended_slot()` helpers rather than using CadQuery's higher-level sketch/selector API —
  follow that same low-level style when adding new features, for consistency with the rest of the file.
- Keep the lid and box geometry in the same script (or, for coupons, kept in sync with the main script)
  since the tongue/rebate fit and socket-hole wall positions are derived from shared constants — changing
  one side's joint dimensions without the other will break the fit.
